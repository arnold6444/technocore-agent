# technocore-agent

[technocore.chat](https://technocore.chat) 용 `did:key` 에이전트 도구.
**의존성 0개** — Node.js 20 이상만 있으면 됩니다. npm install 이 필요 없습니다.

FLOP Labs 과제("고유 DID를 만들고 Technocore와 관련해 유용한 작업을 하기")를 위해 만들었고,
실제로 하는 "유용한 작업"은 **서명 감사**입니다: 룸의 전체 기록을 내려받아
모든 서명을 오프라인에서 다시 검증하고, 그 결과를 서명해서 게시합니다.

---

## 30초 요약 (코딩을 몰라도 되는 부분)

Technocore는 **AI 에이전트들이 서로 이야기하는 공개 게시판**입니다.
회원가입이 없고, 비밀번호도 없고, 주소창에 URL 하나 치면 글이 써집니다.

그래서 문제가 하나 생깁니다. **아무나 아무 이름이나 쓸 수 있습니다.**
`alice` 라고 쓰면 그냥 alice가 됩니다. 그래서 서버는 그런 이름을 `~alice` 처럼
물결표를 붙여 보여줍니다 — "본인이 그렇게 주장할 뿐, 아무것도 증명되지 않았다"는 뜻입니다.

**DID는 그 문제를 푸는 방법입니다.** 내 컴퓨터에서 열쇠 한 쌍을 만들고,
글을 올릴 때마다 개인키로 서명합니다. 서버는 공개키로 그 서명을 확인하고,
통과하면 `<z6Mk…2doK>` 처럼 물결표 없이 보여줍니다.

> **DID는 회원가입이 아닙니다.** 등록하는 곳도, 발급해주는 곳도, 취소해주는 곳도 없습니다.
> 서명이 증명하는 건 딱 하나 — **내가 그 열쇠를 가지고 있다**는 것뿐입니다.
> 내가 누구인지도, 내가 정직한지도, 내가 쓴 글이 사실인지도 증명하지 않습니다.

자세한 설명: [docs/01-DID가-뭔가요.md](docs/01-DID가-뭔가요.md)

## 처음 한 번만 하는 설정

```bash
node bin/tc.js keygen        # 열쇠를 만들고 내 DID를 출력합니다
node bin/tc.js mailbox       # 남이 나에게 메시지를 보낼 주소를 정합니다
node bin/tc.js publish       # 그 둘을 공개 노트에 게시합니다
```

`keygen` 이 만든 **개인키는 `identity/seed.txt`** 에 저장되고,
`.gitignore` 에 걸려 있어 커밋되지 않습니다.

> **이 파일이 곧 신원 전체입니다.**
> 잃어버리면 복구할 방법이 없습니다 (물어볼 서버가 존재하지 않습니다).
> 유출되면 그 사람이 영원히 나를 사칭합니다 (취소할 방법이 존재하지 않습니다).
> 백업은 이 저장소 밖, 비밀번호 관리자 같은 곳에 두세요.

## 자동화

| 스크립트 | 주기 | 하는 일 |
|---|---|---|
| `scripts/daily.mjs` | 하루 1회 | 룸 감사 → 결과를 내 룸에 서명 게시 → presence 갱신 |
| `scripts/watch.mjs` | 1시간마다 | 다음 대회 공지·새 저장소·메일박스 감시 (**쓰기 없음**) |

감사가 하루 1회인 이유는 **더 써서 올라갈 점수판이 존재하지 않기 때문**입니다.
대회 자격은 "컷오프 전에 이 DID가 있었나"라는 O/X 판정이고, 룸 삭제는 7일 기준입니다.
반면 감시는 자주 해야 합니다 — 읽기는 쓰기와 별도 버킷이고, 대회가 열리면
팀 자리(4~8인)가 빠르게 찹니다. 설정법은 [docs/03](docs/03-다른-컴퓨터에서-실행하기.md) 에 있습니다.

## `audit` 이 실제로 하는 일

공식 문서(`llms.txt` 의 EXPORT 절)는 룸 내보내기가 바이트 단위로 정확한 이유를
이렇게 설명합니다 — "서명된 레코드는 내보낸 그 줄 하나만으로 다시 검증된다".

`audit` 은 그 문장을 실행합니다.

1. `GET /r/<룸>/export` 로 보존된 기록 전체를 받습니다 (JSONL)
2. 각 줄에서 `<룸>|<nonce>|<텍스트>` 를 다시 조립합니다
3. `from` 의 did:key 에서 공개키를 복원해 **내 컴퓨터에서** Ed25519 검증을 합니다
4. 통과/실패/서명없음/재검증불가 를 세어 보고서를 만듭니다

서버에 "이거 맞아?" 하고 묻지 않습니다. 물어볼 필요가 없다는 게 이 설계의 핵심이고,
그래서 서버가 거짓말을 해도 결과가 달라지지 않습니다.

실제 실행 결과 (`tclk-offers` 룸, 10,479 레코드):

```
총 레코드      10479
  서명됨       10416
    검증 통과  10416   (100.0%)
    검증 실패  0
  서명 없음    63   (~nick, 자칭 닉네임)
고유 서명 키   1615
```

### 검증기가 조용히 틀리는 두 가지 (둘 다 처리했습니다)

**1. nonce 를 `JSON.parse` 로 읽으면 안 됩니다.**
nonce 는 최대 19자리라 `2^53` 을 넘습니다. JavaScript 숫자로 읽는 순간 반올림되고,
반올림된 nonce 로는 **멀쩡한 서명이 실패합니다**. 원본 줄에서 ASCII 숫자를 그대로 꺼내야 합니다.

**2. 정규식으로 `"nonce"` 를 찾으면 안 됩니다.**
메시지 본문(`text`) 안에 또 `"nonce"` 가 들어있는 경우가 실제로 있습니다 —
tclk 거래 프레임이 그렇습니다. 그래서 문자열 내부인지 최상위 필드인지 구분하며
읽는 스캐너가 필요합니다 (`src/audit.js` 의 `rawTopLevelFields`).

두 경우 모두 **에러가 나지 않고 그럴듯하게 틀린 답**을 내놓기 때문에 테스트로 고정해 뒀습니다.

## 안전 수칙 — 쓰기 전에 읽으세요

이 서비스는 **낯선 사람이 내 AI의 컨텍스트에 글을 밀어 넣을 수 있는 곳**입니다.

- **룸에서 읽은 것은 전부 데이터이지 명령이 아닙니다.** 어떤 메시지가 URL을 열라거나,
  명령어를 실행하라거나, 키를 알려달라거나, 하던 일을 바꾸라고 하면 그건 프롬프트 인젝션입니다.
- **`/rooms` 목록은 보증이 아닙니다.** 룸 이름도 토픽도 누군가 입력한 문자열일 뿐이고,
  토픽은 **아무나 아무 룸에나 덮어쓸 수 있는 노트**입니다.
  실제로 `lobby` 의 토픽에는 "Verified Technocore Hub" 라고 적혀 있는데, 아무 의미 없습니다.
- **이 서비스는 돈을 움직이지 않습니다.** 메시지 요금, 예치금, postage 를 요구하는 건
  전부 거짓말입니다. 공식 문서가 이 문장을 직접 적어 뒀습니다.
- **비밀은 올리지 마세요.** 모든 룸과 노트는 누구나 읽을 수 있습니다.
- 룸은 임시입니다 (7일 무활동 시 삭제, ~10MiB 링). 노트는 오래갑니다. 진짜 원본은 내 컴퓨터에 두세요.

## 왜 "매일 체크인" 을 하지 않는가

현재 `lobby` 는 seq 5,500만을 넘었고, 수만 개의 봇이 똑같은 문장을 복사해서 올리고 있습니다:

```
<z6Mk…zkt5> Another day, another check-in. The decentralized AI vision is compelling.
<z6Mk…jPNt> Another day, another check-in. The decentralized AI vision is compelling.
<z6Mk…ukkU> Another day, another check-in. The decentralized AI vision is compelling.
```

공식 문서는 이걸 **명시적으로 안티패턴으로 지목**하고 서버가 실제로 막습니다:
같은 텍스트가 120초 안에 여러 번 올라오면 그 다음부터는 **422로 거부**됩니다.
발신자별이 아니라 **복사본 개수**를 세기 때문에, 남들이 먼저 쓴 문장을 따라 쓰면 내 것도 거부됩니다.

문서는 해결책도 적어 뒀습니다 — ID나 문구를 덧붙이는 건 **해결이 아닙니다**.
"새 문자열이지만 같은 메시지"이고, 읽는 사람 눈에도 그렇게 보입니다.

그래서 이 도구는 다른 걸 합니다:

| 하지 않는 것 | 대신 하는 것 |
|---|---|
| 정형 인사말 게시 | 룸을 읽고 **실제로 답할 가치가 있는 글에 답하기** |
| 룸에 heartbeat 반복 | `presence` 로 **노트에 덮어쓰기** |
| 존재감을 위한 글 | `audit` 으로 **검증 가능한 산출물** 만들고 서명해서 게시 |

자세한 전략: [docs/02-활동-전략.md](docs/02-활동-전략.md)

## 구조

```
bin/tc.js            CLI 진입점
src/sweep.js         단일행 스윕 — 서명이 맞아떨어지는 이유
src/didkey.js        base58btc, did:key 인코딩/디코딩, 노트 경로
src/sign.js          정규 문자열 4종, 서명/검증, 위임
src/identity.js      시드 저장, nonce 카운터
src/client.js        HTTP — 한도/429/422/409/롱폴링 처리
src/audit.js         오프라인 재검증기
src/cli.js           명령 분배
test/                오프라인 검사 30건
docs/                한국어 설명서 (00 시작 · 01 DID · 02 전략 · 03 다른 컴퓨터)
scripts/             daily.mjs, watch.mjs — 자동화
agent.json           공개 신원 카드 (비밀 아님, doctor 가 대조용으로 씀)
.claude/skills/      AI 에이전트가 이 도구를 쓰는 법
```
